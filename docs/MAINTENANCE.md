## Обзор

### Роль администратора

Администратор отвечает за:

- ✅ Управление пользователями (создание, блокировка, назначение ролей)
- ✅ Поддержку актуальности каталога (цены, модели, параметры)
- ✅ Настройку коэффициентов для расчёта доплат
- ✅ Мониторинг работы системы
- ✅ Резервное копирование данных
- ✅ Обновление приложения

### Доступы

Для полного администрирования необходимы:

- **Аккаунт с ролью `admin`** в приложении
- **Доступ к Firebase Console** (консоль Firebase)
- **Доступ к GitHub репозиторию** (для обновлений кода)
- **Firebase CLI** (для деплоя обновлений)

## Управление пользователями

### Создание нового пользователя

#### Вариант 1: Через Firebase Console (рекомендуется)

1. Откройте [Firebase Console](https://console.firebase.google.com/)
2. Выберите проект
3. Перейдите в **Authentication** → **Users**
4. Нажмите **Add User**
5. Введите:
   - **Email:** адрес почты пользователя
   - **Password:** временный пароль (минимум 6 символов)
6. Нажмите **Add User**
7. Скопируйте **User UID** (понадобится для следующего шага)

#### Шаг 2: Добавить запись в Firestore

1. В Firebase Console перейдите в **Firestore Database**
2. Откройте коллекцию `users`
3. Нажмите **Add document**
4. **Document ID:** вставьте скопированный User UID
5. Добавьте поля:
   ```
   email: "user@example.com" (string)
   role: "user" (string)
   isActive: true (boolean)
   createdAt: [текущая дата] (timestamp)
   ```
6. Нажмите **Save**

#### Шаг 3: Отправить данные пользователю

Отправьте новому пользователю:

- **Email:** указанный email
- **Временный пароль:** созданный пароль
- **Ссылка на приложение:** https://ваш-проект.web.app
- **Инструкция:** при первом входе сменить пароль

---

### Блокировка пользователя

#### Через приложение (быстро)

1. Войдите как администратор
2. Перейдите в **Админ** → **Пользователи**
3. Найдите пользователя
4. Нажмите **«Заблокировать»**

**Результат:** Пользователь мгновенно разлогинен и не может войти.

#### Через Firebase Console

1. Откройте **Authentication** → **Users**
2. Найдите пользователя
3. Нажмите три точки → **Disable user**

**И** обновите запись в Firestore:

1. Откройте **Firestore Database** → `users` → [UID пользователя]
2. Измените поле `isActive` на `false`

---

### Разблокировка пользователя

1. В админ-панели приложения нажмите **«Разблокировать»**

**Или** через Firebase Console:

1. **Authentication:** Enable user
2. **Firestore:** `isActive = true`

---

### Смена роли пользователя

#### Через приложение

1. В разделе **Пользователи** нажмите на роль
2. Выберите **«admin»** или **«user»**

**⚠️ Внимание:** Администраторы имеют полный доступ к системе!

#### Через Firestore

1. Откройте документ пользователя в `users`
2. Измените поле `role`:
   - `"admin"` — полный доступ
   - `"user"` — доступ только к конфигуратору

---

### Удаление пользователя

1. В **Firebase Authentication** удалите пользователя
2. В **Firestore** → `users` удалите документ с его UID
3. (Опционально) В **Firestore** → `history` удалите все документы с его `userId`

**⚠️ Внимание:** Удаление необратимо!

## Управление каталогом

### Структура каталога в Firestore

Каталог хранится в документе:

```
Firestore → catalog → catalog
```

**Основные разделы:**

- `series` — список серий (ML, LS)
- `models` — объект моделей (ключ = model ID)
- `locks` — объект замков (ключ = lock ID)
- `surcharges` — коэффициенты доплат

---

### Добавление новой модели

#### Шаг 1: Подготовить данные

Соберите информацию:

- **ID модели** (например, `ml-30-90`)
- **Название** (ML-30-90)
- **Серия** (`ml` или `ls`)
- **Артикул** (МЛ-30-90-У)
- **Базовая цена** (₽)
- **Стандартные параметры:**
  - Ширина, высота, глубина (мм)
  - Толщина корпуса/двери (мм)
  - Цвет корпуса/двери (RAL)
  - Замок по умолчанию
  - Вентиляция (да/нет)
- **Вес** (кг)
- **Срок изготовления** (дней)
- **Фото модели** (JPG/PNG)

#### Шаг 2: Загрузить фото

1. Подготовьте фото в формате JPG/PNG
2. Переименуйте: `ml-30-90.jpg`
3. Загрузите в `public/img/`

**Через Firebase Storage (если используется):**

1. Откройте Firebase Console → **Storage**
2. Загрузите фото в папку `img/`
3. Скопируйте публичную ссылку

#### Шаг 3: Добавить модель в Firestore

1. Откройте **Firestore Database** → `catalog` → `catalog`
2. Нажмите **Edit document**
3. Перейдите в поле `models`
4. Добавьте новый ключ `ml-30-90`:

```json
{
  "id": "ml-30-90",
  "name": "ML-30-90",
  "seriesId": "ml",
  "article": "МЛ-30-90-У",
  "basePrice": 14000,
  "defaultSpecs": {
    "width": 900,
    "height": 1800,
    "depth": 500,
    "bodyThickness": 0.5,
    "doorThickness": 0.5,
    "bodyColorName": "RAL 7038",
    "doorColorName": "RAL 7038",
    "lockId": "rigel",
    "hasVentilation": false
  },
  "weight": 50,
  "productionTime": 12,
  "photo": "/img/ml-30-90.jpg"
}
```

5. Нажмите **Update**

#### Шаг 4: Проверить

1. Откройте приложение
2. Выберите серию ML
3. Убедитесь, что новая модель отображается

**💡 Подсказка:** Очистите кеш браузера (`Ctrl+Shift+Delete`), если модель не появилась.

---

### Редактирование модели

#### Изменение цены

1. Откройте **Firestore** → `catalog` → `catalog`
2. Найдите модель в `models.ml-30-90`
3. Измените поле `basePrice`
4. Нажмите **Update**

**Результат:** Цена обновится в приложении в течение 24 часов (кеш) или сразу после очистки кеша.

#### Изменение параметров

Аналогично измените нужные поля в `defaultSpecs`:

- `width`, `height`, `depth` — габариты
- `bodyThickness`, `doorThickness` — толщина
- `bodyColorName`, `doorColorName` — цвета
- `lockId` — замок по умолчанию
- `hasVentilation` — вентиляция

---

### Удаление модели

1. Откройте **Firestore** → `catalog` → `catalog`
2. Найдите модель в `models`
3. Удалите ключ (например, `ml-30-90`)
4. Нажмите **Update**

**⚠️ Внимание:** Модель исчезнет из каталога для всех пользователей!

---

### Сортировка каталога

Порядок отображения моделей определяется порядком ключей в объекте `models`.

**Проблема:** В Firestore объекты с числовыми строковыми ключами сортируются в числовом порядке автоматически.

**Решение:** Используйте drag & drop в админ-панели:

1. Войдите как администратор
2. Перейдите в **Админ** → **Каталог**
3. Нажмите **«Сортировка»**
4. Перетаскивайте модели в нужном порядке
5. Нажмите **«Сохранить»**

## Настройка коэффициентов

### Типы коэффициентов

1. **Глубина** (`surcharges.depth`) — доплата за нестандартную глубину
2. **Высота** (`surcharges.height`) — доплата за нестандартную высоту
3. **Толщина корпуса** (`surcharges.bodyThickness`) — доплата за толстый металл
4. **Толщина двери** (`surcharges.doorThickness`) — доплата за толстую дверь
5. **Вентиляция** (`surcharges.ventilation`) — доплата за вентиляцию
6. **Цвет** (`surcharges.color`) — доплата за нестандартный цвет

---

### Формат коэффициентов

#### По объёму заказа

```json
{
  "1-9": 1.15,
  "10-49": 1.10,
  "50-99": 1.05,
  "100+": 1.00
}
```

**Объяснение:**

- При заказе 1-9 шт. — коэффициент 1.15 (доплата +15%)
- При заказе 10-49 шт. — коэффициент 1.10 (доплата +10%)
- При заказе 50-99 шт. — коэффициент 1.05 (доплата +5%)
- При заказе 100+ шт. — коэффициент 1.00 (без доплаты)

#### По параметру

```json
{
  "0.5": 1.00,
  "0.6": 1.10,
  "0.7": 1.20
}
```

**Объяснение:**

- Толщина 0.5 мм — без доплаты
- Толщина 0.6 мм — +10%
- Толщина 0.7 мм — +20%

---

### Редактирование коэффициентов

#### Через админ-панель (рекомендуется)

1. Войдите как администратор
2. Перейдите в **Админ** → **Коэффициенты**
3. Выберите тип коэффициента
4. Измените значения в таблице
5. Нажмите **«Сохранить»**

**Результат:** Изменения применяются мгновенно.

#### Через Firestore

1. Откройте **Firestore** → `catalog` → `catalog`
2. Найдите `surcharges.depth` (или другой тип)
3. Измените значения
4. Нажмите **Update**

---

### Пример: Изменение коэффициента глубины

**Задача:** Увеличить доплату за нестандартную глубину для мелких заказов.

**До:**

```json
{
  "1-9": 1.15,
  "10-49": 1.10,
  "50-99": 1.05,
  "100+": 1.00
}
```

**После:**

```json
{
  "1-9": 1.20,
  "10-49": 1.15,
  "50-99": 1.10,
  "100+": 1.00
}
```

**Результат:** Цена для заказов 1-9 шт. с нестандартной глубиной увеличится на 5%.

## Резервное копирование

### Экспорт данных из Firestore

#### Вариант 1: Через Firebase Console (вручную)

1. Откройте **Firestore Database**
2. Выберите коллекцию (например, `catalog`)
3. Нажмите **Export** (если доступно)
4. Сохраните JSON-файл

**⚠️ Внимание:** Не все планы Firebase поддерживают экспорт через консоль.

#### Вариант 2: Через gcloud CLI (автоматизированно)

```bash
# Установить gcloud CLI
# https://cloud.google.com/sdk/docs/install

# Авторизоваться
gcloud auth login

# Экспорт Firestore
gcloud firestore export gs://ваш-bucket/backup/$(date +%Y%m%d)
```

---

### Регулярные резервные копии

**Рекомендация:** Делайте резервные копии каталога **еженедельно**.

**Способ:** Настройте Cloud Scheduler + Cloud Functions для автоматического экспорта.

**Или вручную:**

1. Каждую неделю экспортируйте коллекцию `catalog`
2. Сохраняйте JSON-файлы в безопасном месте (Google Drive, Dropbox)

---

### Восстановление из резервной копии

1. Откройте **Firestore** → `catalog` → `catalog`
2. Нажмите **Edit document**
3. Скопируйте содержимое из резервной копии (JSON)
4. Вставьте в поля документа
5. Нажмите **Update**

**⚠️ Внимание:** Это перезапишет текущий каталог!

## Мониторинг

### Firebase Console

#### Authentication

1. Откройте **Authentication** → **Users**
2. Проверьте количество активных пользователей
3. Смотрите **Sign-in method** — статистику входов

#### Firestore

1. Откройте **Firestore Database**
2. Проверьте размер базы данных
3. Смотрите **Usage** — количество операций чтения/записи

**Лимиты Spark Plan (бесплатный):**

- 50,000 операций чтения/день
- 20,000 операций записи/день
- 1 ГБ хранилища

**Если превышены:** Переключитесь на Blaze Plan (оплата по факту).

#### Hosting

1. Откройте **Hosting**
2. Проверьте **Traffic** — количество посещений
3. Смотрите **Bandwidth** — объём переданных данных

## Обновление приложения

### Обновление кода

1. Получите новый код из репозитория:

```bash
cd /path/to/Promet
git pull origin main
```

2. Установите обновлённые зависимости:

```bash
npm install
```

3. Соберите проект:

```bash

```

4. Проверьте билд локально:

## Решение проблем

### Пользователи не могут войти

**Симптом:** Пользователи получают ошибку при попытке входа.

**Причины:**

1. **Firebase Authentication отключен**
   - Решение: Откройте **Authentication** → **Sign-in method** → включите Email/Password

2. **Firestore правила блокируют доступ**
   - Решение: Проверьте `firestore.rules` — убедитесь, что авторизованные пользователи могут читать

3. **Пользователь заблокирован**
   - Решение: Разблокируйте пользователя в админ-панели или Firebase Console

---

### Каталог не обновляется после изменений

**Симптом:** Изменения в Firestore не отображаются в приложении.

**Причины:**

1. **Кеширование в localStorage**
   - Решение: Очистите кеш браузера (`Ctrl+Shift+Delete`) или подождите 24 часа

2. **Проблемы с Firestore**
   - Решение: Проверьте **Firestore Database** — убедитесь, что изменения сохранились

---

### PDF не генерируются

**Симптом:** При нажатии «Скачать КП» ничего не происходит.

**Причины:**

1. **Отсутствуют шаблоны PDF**
   - Решение: Проверьте `public/templates/` — убедитесь, что файлы на месте

2. **Отсутствуют шрифты**
   - Решение: Проверьте `public/fonts/` — должны быть файлы Montserrat

3. **Ошибка в коде**
   - Решение: Откройте консоль (`F12`) и проверьте ошибки

---

### Приложение работает медленно

**Симптом:** Долгая загрузка страниц, тормоза.

**Причины:**

1. **Большой каталог**
   - Решение: Оптимизируйте изображения (сжимайте JPG до 100-200 КБ)

2. **Превышены лимиты Firestore**
   - Решение: Переключитесь на Blaze Plan

3. **Много активных пользователей**
   - Решение: Масштабируйте инфраструктуру (обратитесь к разработчику)

## Безопасность

### Лучшие практики

1. **Пароли администраторов**
   - Минимум 12 символов
   - Включайте буквы, цифры, спецсимволы
   - Меняйте каждые 3 месяца

2. **Firestore Security Rules**
   - Регулярно проверяйте правила доступа
   - Никогда не открывайте полный доступ (`allow read, write: if true`)

3. **Firebase API Keys**
   - Не коммитьте `.env` в Git
   - Храните резервную копию в безопасном месте

4. **Регулярные обновления**
   - Обновляйте зависимости npm раз в месяц
   - Следите за уведомлениями о безопасности

---

### Проверка безопасности

```bash
# Проверить уязвимости в зависимостях
npm audit

# Исправить автоматически
npm audit fix

# Если есть критические уязвимости
npm audit fix --force
```

2. Проверьте **Activity** — подозрительные входы
3. Если видите неизвестные IP — заблокируйте пользователя
