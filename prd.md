# PRD — Веб-конфигуратор металлических шкафов-локеров «Промет»

**Версия:** 1.0
**Дата:** 31 марта 2026
**Статус:** В разработке
**Разработчик:** 1 frontend-разработчик
**Стейкхолдер:** менеджер (принимает работу по частям)
**Валидация продукта:** фокус-группа директоров филиалов после выпуска MVP

---

## 1. Обзор продукта

### 1.1 Описание

Веб-конфигуратор металлических шкафов-локеров — внутренний инструмент для менеджеров, специалистов и директоров филиалов ООО «НПО Промет». Позволяет быстро собрать нестандартную конфигурацию изделия (серия, модель, габариты, замок, вентиляция, цвет), сформировать КП для клиента и бланк нестандартного заказа для отправки на завод по электронной почте — чтобы производство сразу приступало к изготовлению.

### 1.2 Проблема, которую решает продукт

Сейчас менеджеры и директора филиалов рассчитывают стоимость вручную по таблицам Excel и формируют КП и бланки нестандартных заказов в Word. Это занимает 20–40 минут на заявку, приводит к ошибкам в спецификациях и задержкам передачи заказа на завод.

### 1.3 Цели продукта

| # | Цель | Метрика успеха |
|---|------|----------------|
| 1 | Сократить время формирования КП и бланка заказа | С 30 мин → до 3 мин |
| 2 | Исключить ошибки в спецификации нестандартных заказов | 0 ошибок в бланках, уходящих на завод |
| 3 | Стандартизировать выходные документы | 100% нестандартных заказов через конфигуратор |
| 4 | Обеспечить единый процесс для всех сотрудников | Любой менеджер или директор филиала самостоятельно оформляет полный пакет документов |

## 2. Пользователи

### 2.1 Целевая аудитория

Все пользователи — внутренние сотрудники ООО «НПО Промет»: **менеджеры по продажам и директора филиалов**. Роли не разделяются — каждый выполняет одинаковый сценарий: собирает конфигурацию по заявке клиента, формирует два документа и отправляет их.

| Кто | Что делает в конфигураторе |
|-----|---------------------------|
| Менеджер по продажам | Принимает заявку → собирает конфигурацию → отправляет КП клиенту + НЗ на завод |
| Директор филиала | Принимает заявку на месте → собирает конфигурацию → отправляет КП клиенту + НЗ на завод |

### 2.2 Пользовательский путь

```
Открыл конфигуратор
  → выбрал серию и модель (базовая цена подгружается из Firebase)
  → задал нестандартные параметры: габариты, замок, вентиляция, цвета
    └─ каждый нестандартный параметр добавляет наценку к базовой цене
  → проверил итоговую конфигурацию и цену
  → нажал «КП для клиента» → скачал PDF → отправил клиенту вручную через Outlook
  → нажал «Бланк НЗ»       → скачал PDF → отправил на завод вручную через Outlook
```

## 3. Функциональные требования

### 3.1 Конфигурация изделия (P0 — критично)

#### 3.1.1 Выбор серии и модели

- Список серий и моделей загружается из **Firebase** — никаких хардкодированных значений
- При выборе модели из Firebase подтягиваются её стандартные параметры: габариты, базовый замок, цвет, артикул, базовая цена
- При смене серии — список моделей обновляется, текущий выбор сбрасывается

| Параметр | Источник данных | Поведение |
|----------|-----------------|-----------|
| Серия | Firebase | Определяет доступные модели |
| Модель | Firebase | Загружает стандартную спецификацию и базовую цену |

#### 3.1.2 Толщина металла

- Значения: 0.5 мм / 0.6 мм / 0.7 мм
- Стандартная толщина для всех моделей — **0.5 мм** (входит в базовую цену, наценка 0 ₽)
- Выбор 0.6 мм или 0.7 мм → наценка к цене + параметр попадает в карточку «Нестандартное исполнение»
- Реализация: переключатель (toggle-group), не dropdown

#### 3.1.3 Габариты

- При выборе модели поля ширины и высоты автоматически заполняются стандартными значениями из Firebase
- Пользователь может изменить значения — тогда параметр считается нестандартным и попадает в карточку «Нестандартное исполнение»
- Реализация: числовые поля (input type="number")
- При выходе за допустимый диапазон — показать ошибку, заблокировать расчёт

| Параметр | Значение по умолчанию | Источник |
|----------|----------------------|----------|
| Ширина | стандарт модели | Firebase |
| Высота | стандарт модели | Firebase |

#### 3.1.4 Тип замка

- Всегда 5 вариантов замка
- Названия и наценки загружаются из **Firebase** (не хардкодируются)
- Первый замок в списке — базовый (входит в стандарт, наценка 0 ₽)
- Реализация: список с радио-выбором, наценка отображается рядом с названием
- Выбор не базового замка → параметр попадает в карточку «Нестандартное исполнение»

#### 3.1.5 Вентиляция

- Значения: Да / Нет
- Реализация: две кнопки (Yes/No toggle)
- При выборе «Да» — наценка к цене и добавляется в карточку «Нестандартное исполнение»

#### 3.1.6 Цвет корпуса и дверцы

- Два независимых ColorPicker (корпус / дверца)
- Список цветов, их группировка, названия и цены загружаются из **Firebase**
- Каждый цвет в Firebase: RAL-код, hex, человекочитаемое название, наценка
- Цена изделия меняется в зависимости от выбранного цвета
- Выбор небазового цвета → параметр попадает в карточку «Нестандартное исполнение»

### 3.2 Отображение конфигурации (P0)

#### 3.2.1 Три колонки результата

| Колонка | Содержимое | Стиль |
|---------|------------|-------|
| Стандартное исполнение | Заводские параметры выбранной модели по умолчанию (из Firebase) | Белая карточка |
| Нестандартное исполнение | Только параметры, отличающиеся от стандарта | Янтарная карточка |
| Итоговая конфигурация | Все выбранные параметры + итоговая цена + кнопки экспорта | Тёмно-синяя карточка |

**Логика карточки «Нестандартное исполнение»:**
- Отображается только то, что пользователь изменил относительно стандарта
- Небазовый замок → показать
- Вентиляция = Да (если в стандарте нет) → показать
- Цвет, отличный от стандартного → показать
- Габариты, отличные от стандартных → показать
- Если ничего не менялось — карточка пуста или скрыта

**Итоговая карточка:**
- Всегда показывает все параметры конфигурации
- Итоговая цена (базовая + все наценки)
- Кнопка «КП для клиента» — скачать PDF
- Кнопка «Бланк НЗ» — скачать PDF и отправить на завод

#### 3.2.2 Итоговая цена

- Формула: `Базовая цена модели (из Firebase) + сумма наценок за каждый нестандартный параметр`
- Нестандартные параметры, влияющие на цену: замок (не базовый), вентиляция (Да), цвет (не базовый), габариты (не стандартные)
- Отображение: крупно в итоговой колонке, формат `14 200 ₽`
- Пересчёт в реальном времени при изменении любого параметра

#### 3.2.3 Артикул изделия

- Загружается из **Firebase** вместе с данными выбранной модели
- Отображается под заголовком конфигурации

### 3.3 Экспорт документов (P1 — важно)

#### 3.3.1 КП для клиента (коммерческое предложение)

- Формат: PDF
- Содержимое:
  - Шапка с логотипом Промет
  - Полная конфигурация изделия
  - Цена с разбивкой по опциям
  - Контакты менеджера — загружаются из **Firebase**
  - Дата и срок действия КП

#### 3.3.2 Бланк НЗ (нестандартного заказа, для завода)

- Формат: PDF, скачивается кнопкой «Бланк НЗ»
- Содержимое:
  - Шапка с реквизитами и датой
  - Полная техническая спецификация: серия, модель, артикул
  - Все нестандартные параметры (габариты, толщина, замок, вентиляция, RAL-коды корпуса и дверцы)
  - Итоговая цена изделия
  - Место для подписи ответственного лица
- **Отправка на завод — вручную:** пользователь скачивает PDF и прикрепляет его к письму в Outlook самостоятельно. Автоматической отправки нет.

### 3.4 Личный кабинет (P2 — планируется)

- Авторизация (логин/пароль)
- История конфигураций и отправленных бланков
- Сохранение черновиков
- Роли: сотрудник (менеджер / директор филиала) / администратор

### 3.5 Интеграция с Firebase (P1 — планируется)

Firebase — единственный бэкенд проекта. Используется как база данных для хранения каталога и как хостинг.

**Структура данных в Firestore:**
- `series` — список серий
- `models` — модели с привязкой к серии, стандартными габаритами, артикулом, базовой ценой
- `locks` — 5 типов замков с названиями и наценками
- `colors` — цвета с RAL-кодом, hex, названием, наценкой
- `contacts` — контактные данные менеджеров для подстановки в КП

**Поведение при загрузке:**
- При открытии приложения — загружается каталог из Firebase
- Данные кэшируются на сессию, повторные запросы не нужны
- Если Firebase недоступен — показать ошибку загрузки

## 4. Нефункциональные требования

### 4.1 Производительность

| Требование | Цель |
|------------|------|
| Время пересчёта цены | < 50 мс (клиентский расчёт) |
| Первая загрузка страницы | < 2 сек на 4G |
| Генерация PDF | < 5 сек |
| Bundle size | < 500 KB gzip |

### 4.2 Совместимость браузеров

- Chrome 110+
- Firefox 110+
- Safari 16+
- Edge 110+
- Мобильные браузеры: поддержка адаптивного отображения (не основной сценарий)

### 4.3 Безопасность

- HTTPS обязателен
- Аутентификация через Firebase Auth — токены управляются Firebase автоматически
- Нет хранения чувствительных данных в localStorage без шифрования

### 4.4 Доступность (Accessibility)

- Keyboard navigation для всех форм-контролов
- ARIA-атрибуты для ColorPicker и кастомных dropdown
- Контрастность текста: минимум WCAG AA

## 9. Ограничения и допущения

- Конфигуратор работает только с металлическими шкафами-локерами (не другие продуктовые линейки)
- Все пользователи — внутренние сотрудники Промет, публичного доступа нет
- Единственный бэкенд — Firebase (Firestore + Firebase Auth); интеграция с 1С не предусмотрена
- 3D-превью не входит в проект — исключено из-за высокой стоимости разработки
- Сейчас данные (серии, модели, замки, цвета) — временные заглушки; будут заменены на данные из Firebase (перенос из Excel)
- Отправка документов — только скачивание PDF; пользователь сам прикрепляет файл и отправляет через Outlook
- Firebase Auth настраивает разработчик самостоятельно; пользователи не регистрируются сами
- После выпуска MVP — фокус-группа с директорами филиалов для сбора обратной связи
- Мобильная версия — отображение корректное, UX-оптимизация под мобильные устройства отложена
