## Phase 1: Frontend MVP ✓

**Goal:** Рабочий конфигуратор с реальными данными, diff-логикой и базовым расчётом цены.

**Status:** ✓ Выполнено (2026-04-01)

**Закрывает требования:** CONF_1–14, DOC_6, UX_1, UX_2

**Что реализовано:**
- `App.jsx` — state поднят, config передаётся через props
- `src/utils/calcDiff.js` — diff по 10 полям
- `src/api/loadCatalog.js` — загрузка каталога из Firebase Firestore REST API
- Configurator: три колонки, анимации строк (0.4s cubic-bezier)
- Parameters: 11 блоков управления параметрами со степпером ±50мм
- Header: логотип Промет, декоративные города, фон #0C53B3, высота 99px
- Кнопки КП/НЗ заблокированы без выбранной модели

## Phase 2: Формула расчёта цены + UX-улучшения

**Goal:** Внедрить точную формулу расчёта итоговой цены при нестандартном заказе.

**Status:** ⏳ Ожидает встречи с менеджерами (технические задачи выполнены, UX-улучшения завершены)

**Закрывает требования:** CONF_12 (полностью, сейчас заглушка)

**Что нужно получить от менеджеров:**
- Как считается доплата за изменение габаритов (ширина, высота, глубина)?
- Как считается доплата за изменение толщины металла корпуса и двери?
- Суммы доплат за каждый замок (навесной, кодовый, сувальдный, электронный)
- Доплата за вентиляцию — фиксированная сумма?
- Доплата за нестандартный цвет RAL
- Есть ли минимальная цена? Округление?

**Milestones:**

_Выполнено (не требовали формулу):_
1. ✅ API-ключ Firebase вынести в `.env` (SEC_3)
2. ✅ Firestore rules — запретить запись из браузера (SEC_1)
3. ✅ localStorage кэш каталога как fallback (PERF_4)
4. ✅ Кнопка «Повторить» при ошибке загрузки (REL_2 / UX_3)
5. ✅ Анимированный степпер навигации (motion v12)
6. ✅ Кнопка сброса параметров
7. ✅ Взаимная блокировка дропдаунов
8. ✅ Копирование артикула, sticky-плашка мобильных
9. ✅ Оранжевая обводка при изменении параметров, бейдж на шаге 3
10. ✅ Количество шкафов на шаге 2
11. ✅ Синхронизация Google Sheets → Firebase; loadCatalog напрямую из Firestore

_Ждут формулу от менеджеров:_
12. Занести коэффициенты доплат в Google Sheets + Firebase
13. Реализовать полную `calcPrice(config, catalog)` по точной формуле (сейчас нет доплат за толщину)
14. Проверить на 3–5 реальных примерах вместе с менеджерами

**Success Criteria:**
1. API-ключ не виден в публичном коде (SEC_3)
2. Из браузера нельзя изменить данные каталога (SEC_1)
3. При недоступности Firebase — каталог грузится из кэша (PERF_4)
4. При ошибке загрузки видна кнопка «Повторить» (REL_2)
5. Цена стандартного шкафа = цена из таблицы
6. Цена пересчитывается при изменении любого параметра
7. Менеджер подтверждает корректность расчёта

**Отложено в этой фазе (deferred):**
- DOC_1, DOC_2 (КП для клиента) — отдельный popup, контакты менеджера, срок действия КП
- Сохранение истории скачиваний — Phase 4

**Что заполняет приложение в форме НЗ (раздел I):**
- Поле 1: Менеджер по продажам (Ф.И.О.) — из popup
- Поле 2: Название Клиента (страна) — из popup
- Таблица 3: Артикул, Наименование, Кол-во — из config + catalog
- Поле 6: Отличия от серийной продукции — все 11 параметров с маркировкой нестандартных

**Что остаётся пустым** (заполняет завод вручную): остальные поля раздела I (4, 5, 5.1, 7, 8) и разделы II–V.

**Success Criteria:**
1. PDF «НЗ» содержит все поля DOC_4 — артикул, серия, модель, параметры с выделением отклонений
2. Имена файлов соответствуют формату `{артикул}_{YYYY-MM-DD}.pdf`
3. Кнопка «Бланк НЗ» активна только при выбранной модели (DOC_6, уже выполнено)

5. @react-pdf/renderer не входит в initial bundle (PERF_3) — lazy chunk через dynamic import

## Phase 4: Auth + History

**Goal:** Авторизация сотрудников, сохранение и загрузка конфигураций.

**Status:** ○ Заблокирован — после фокус-группы

**Закрывает требования:** AUTH_1, HIST_1, HIST_2, HIST_3

**Нужно уточнить до реализации:**
- Список email сотрудников для Firebase Auth
- Сколько конфигураций хранить на одного пользователя?
- Нужна ли возможность удалять конфигурации из истории?

**Milestones:**
1. Firebase Auth подключён (email + пароль)
2. Экран входа с фирменным стилем Промет
3. `Firestore /users/{uid}/configs` — сохранение конфигурации с датой, моделью, ценой
4. UI списка конфигураций (дата, модель, цена, кнопка «Загрузить»)
5. Загрузка сохранённой конфигурации в конфигуратор (HIST_3)
6. Защита маршрутов — неавторизованный видит только экран входа

**Success Criteria:**
1. Неавторизованный пользователь видит только экран входа (AUTH_1)
2. Конфигурацию можно сохранить с датой, моделью и ценой (HIST_1, HIST_2)
3. Сохранённую конфигурацию можно загрузить обратно в конфигуратор (HIST_3)
4. История показывает дату, модель и итоговую цену
